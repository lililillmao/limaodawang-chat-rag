### 二、功能详述

#### F1 · Skill 加载记录与追溯

**目标**：每条 assistant 消息记录生成时的 Skill 来源，可追溯、可恢复、可导出。

**具体内容**：
- 消息级字段：`skillId`、`skillName`
- 消息头显示 Skill 徽章：`🤖 qwen2.5:7b · 🧩 狸猫 · 12:30`
- 导出 MD/TXT/JSON 时带上 Skill 名
- 重新生成时默认沿用原 Skill，Skill 不一致时弹窗询问
- 切换会话时自动恢复该会话最后使用的 Skill（带“锁定当前 Skill”开关）
- 对比模式两个模型共用同一 Skill

**改动位置**：`js/ui/messages.js`、`js/features/export.js`、`js/state.js`

---

#### F2 · 多平台 API 接入

**目标**：从“只能连 Ollama”升级为“Ollama + 任意 OpenAI 兼容平台”。

**首批支持**：
- Ollama（原生，保留）
- DeepSeek（`https://api.deepseek.com`）
- 通用 OpenAI 兼容（可填 baseUrl 自定义）：Moonshot、SiliconFlow、OpenRouter、智谱、通义、Groq 等

**技术架构**：
```
js/api/
  providers.js   # 统一分发
  ollama.js      # NDJSON 流
  openai.js      # SSE 流（DeepSeek 等走这里）
```

**统一接口**：
```js
provider.listModels(baseUrl, apiKey)
provider.streamChat({baseUrl, apiKey, model, messages, options, signal,
                     onChunk, onDone, onError})
```

**要处理的差异**：
- 思考通道统一：Ollama `message.thinking` / DeepSeek `reasoning_content` / OpenAI `reasoning` → 统一为 `thinking`
- 停止词位置转换
- 发给 API 时剥离思考内容，只发正文
- 429 限流重试与错误提示
- 上下文窗口标注为“估算值”

**配置层**：
- `cfg.providers: [{id, type, name, baseUrl, apiKey, models}]`
- 顶栏模型选择改分组下拉（optgroup）
- 设置面板新增“平台管理”：增删 provider、填 Key、测连通性
- API Key 明文存 localStorage + 显式警告

**跨 provider 对比**：支持 Ollama vs DeepSeek 同台

**待确认**：API Key 是否需要后端代理隐藏（建议 1.20 先不做）

---

#### F3 · index.html 模块化拆分

**目标**：单文件 3000 行 → 多文件模块，功能 100% 不变。

**目录结构**：
```
/
├── index.html              # 只剩结构 + link + script module
├── css/
│   ├── base.css            # 变量、reset、主题
│   ├── layout.css          # sidebar / main / topbar
│   ├── chat.css            # 消息、思考框、代码块、对比
│   ├── input.css           # 输入区、快捷、语音
│   └── modal.css           # 弹窗、设置面板
└── js/
    ├── main.js             # 入口 init()
    ├── config.js           # DEFAULT_CFG、loadLocal、saveLocal、主题
    ├── state.js            # 集中状态管理
    ├── utils.js            # escapeHtml、estimateTokens、copyText
    ├── markdown.js         # renderMarkdown、postRender、replaceEmo
    ├── api/
    │   ├── providers.js
    │   ├── ollama.js
    │   ├── openai.js
    │   └── rag.js
    ├── ui/
    │   ├── sidebar.js
    │   ├── messages.js
    │   ├── input.js
    │   ├── settings.js
    │   └── modals.js
    └── features/
        ├── compress.js
        ├── export.js
        └── nav.js
```

**必须一起做的改造**：
1. 干掉所有 `onclick="fn()"`，改 `addEventListener` 或事件委托
2. 状态集中到 `state.js`，各模块通过 getter/setter 访问

**约束**：
- 不用构建工具，浏览器直接跑
- 必须走 HTTP 访问（`file://` 下 ES module 会被 CORS 拦）
- 前端仍可单独分发，只是从“单文件”变“单文件夹”

**可选项**：提供一个打包脚本，把拆分后的文件合成 `index.single.html` 用于分发

---

#### F4 · 会话级 / 预设级模型参数

**目标**：不同场景用不同参数，不用每次手动改全局设置。

**三级继承**：
```
全局默认  →  预设覆盖  →  会话临时覆盖
```

**参数范围**：`temperature`、`top_p`、`num_ctx`、`num_predict`

**UI**：
- 顶栏加一个快捷参数按钮，点击弹出当前会话的参数面板
- 显示当前值来自哪一级（继承来源提示）
- 预设编辑弹窗增加参数覆盖区

**改动位置**：`js/config.js`、`js/state.js`、`js/ui/settings.js`

---

#### F5 · 消息分支树状视图

**目标**：让分叉不再是“一次性的”，用户能看到自己在树上的位置。

**具体内容**：
- 顶栏或侧边显示面包屑：`主对话 > 分支A > 分支A2`
- 点击任意祖先节点可跳回
- 侧边栏会话项显示分支层级缩进
- 分支会话的标题自动加前缀，如 `└ 分支：xxx`

**数据基础**：现有 `sessions[].messages` 已经支持，只需加 `parentSessionId` 字段

**改动位置**：`js/ui/sidebar.js`、`js/state.js`

---

#### F6 · 拖拽文件到输入框（临时 RAG）

**目标**：临时文档即问即用，不用先入库再重建。

**流程**：
```
拖拽文件 → 前端切片 → 仅本次对话生效的临时向量检索
```

**技术要点**：
- 复用后端切片逻辑，但**不落 ChromaDB**
- 临时索引存内存（或 IndexedDB），会话结束或刷新后清空
- 支持 `.md/.txt/.pdf/.docx/.py` 等已有格式
- 输入框上方显示已拖入文件的 chip，可删除
- 与正式 RAG 可叠加，临时文档优先

**后端配合**：`rag_server.py` 加一个 `/api/embed_temp` 接口，只算向量不入库

**改动位置**：`js/ui/input.js`、`js/api/rag.js`、`rag_server.py`

---

#### F7 · 平台连通性检测

**目标**：接多平台后，用户填错配置能立刻知道。

**具体内容**：
- 每个 provider 一个“测试连接”按钮
- 测试内容：baseUrl 可达 + Key 有效 + 模型列表能拉到
- 返回绿勾 / 红叉 + 具体错误（HTTP 状态、超时、Key 无效）
- 测试结果缓存 5 分钟，避免频繁请求

**改动位置**：`js/ui/settings.js`、`js/api/providers.js`

---

#### F8 · 真实 token 用量显示

**目标**：接 API 后能拿到真实 usage，替代估算值。

**具体内容**：
- 消息头显示真实 prompt / completion token 数
- 会话底部显示本次累计 token
- 本地 Ollama 仍用估算，标注“估算”
- 为后续成本统计预留字段

**改动位置**：`js/ui/messages.js`、`js/api/openai.js`

---

### 三、1.20 实施顺序建议

```
阶段 1：F3 拆分（纯搬家，不新增功能）
   ↓
阶段 2：F1 Skill 记录 + F4 会话参数（此时模块已就位）
   ↓
阶段 3：F2 多平台接入（最大工作量）
   ↓
阶段 4：F7 连通检测 + F8 token 显示（F2 的配套）

阶段 5：F5 分支树 + F6 拖拽文件
   ↓
阶段 6：回归测试 + 打包
```

**关键原则**：F3 必须先做且不夹带新功能，否则回归测试会失控。

## 📦 1.21 版本功能报表

**主题**：体验深化 + 长期记忆 + 生态扩展  
**定位**：在 1.20 稳定地基上做体验质变

### 一、功能清单总览

| 编号 | 功能名称 | 来源 | 优先级 | 预估工作量 |
|---|---|---|---|---|
| G1 | 记忆系统（长期记忆） | 建议6 | P0 | 大 |
| G2 | 按 Skill 做 RAG 命名空间隔离 | 建议7 | P0 | 中 |
| G3 | 多 Skill 叠加 | 建议8 | P1 | 中 |
| G4 | 提示词模板变量 | 建议9 | P1 | 小 |
| G5 | RAG 引用可点击跳转 | 建议10 | P1 | 小 |
| G6 | 工具调用 / MCP 支持 | 建议11 | P2 | 大 |
| G7 | 视觉模型输入 | 建议12 | P2 | 中 |
| G8 | 从 ChatGPT / Claude 导入历史 | 建议13 | P2 | 中 |
| G9 | 数据加密 | 建议14 | P3 | 中 |
| G10 | 成本统计 | 建议15 | P3 | 小 |

---

### 二、功能详述

#### G1 · 记忆系统（长期记忆）

**目标**：让 AI 跨会话记住用户，是角色扮演体验的质变点。

**设计**：
- 每条 assistant 回答后，异步让模型抽一句“值得记的事实”
- 存入独立 `memory.json`，可手动增删改
- 下次对话按相关度检索前 N 条注入 system prompt
- 和 RAG 共用向量库，换一个 collection

**UI**：
- 设置面板新增“记忆管理”区块
- 每条记忆显示内容、来源会话、时间、置信度
- 支持手动添加 / 删除 / 编辑 / 禁用

**技术要点**：复用 RAG 的 embedding 流程，只是 collection 不同

---

#### G2 · 按 Skill 做 RAG 命名空间隔离

**目标**：问狸猫角色时不会检索到别的 Skill 的设定文档。

**设计**：
- Skill 可在 `SKILL.md` front-matter 声明 `rag_scope: self` / `all`
- 检索时在 ChromaDB metadata 上加过滤条件
- 默认 `self`，可手动切换为 `all`

**改动位置**：`rag_server.py` 的 `/api/search`、`SKILL.md` 解析

---

#### G3 · 多 Skill 叠加

**目标**：一次可选多个 Skill，按顺序拼接 system prompt。

**设计**：
- Skill 下拉框改为多选（checkbox 列表）
- 按选择顺序拼接，显示总字数警告
- 支持拖拽调整顺序
- 保存为“Skill 组合”预设，可一键加载

**改动位置**：`js/ui/settings.js`、`js/state.js`

---

#### G4 · 提示词模板变量

**目标**：让快捷模板从“文本片段”变成“小工具”。

**支持的变量**：
- `{{clipboard}}` — 当前剪贴板内容
- `{{selected}}` — 当前选中的文本
- `{{date}}` — 当前日期
- `{{time}}` — 当前时间
- `{{session_title}}` — 当前会话标题

**UI**：模板编辑弹窗加变量插入按钮

---

#### G5 · RAG 引用可点击跳转

**目标**：真正做到“可溯源”。

**设计**：
- 引用片段点击展开全文
- 本地文件给出“打开所在目录”按钮（需后端配合）
- 显示相似度分数
- 支持复制单条引用内容

**后端配合**：`rag_server.py` 加一个 `/api/open_folder` 接口（仅本地可用）

---

#### G6 · 工具调用 / MCP 支持

**目标**：让模型能调用外部工具。

**范围**：
- 支持 OpenAI 格式的 function calling
- 支持 MCP 协议接入本地工具
- 多轮工具调用 UI 展示（工具名、参数、结果）
- 中断与重试

**前置条件**：1.20 的多平台架构稳定

**风险**：Ollama 对 tool calling 支持参差，需按模型做兼容

---

#### G7 · 视觉模型输入

**目标**：拖拽图片到输入框，走多模态模型。

**支持**：llava、qwen-vl、minicpm-v 等

**要处理的兼容**：
- 对比模式下的图片处理
- RAG 检索时图片如何处理
- 导出时的图片引用

---

#### G8 · 从 ChatGPT / Claude 导入历史

**目标**：降低用户迁移成本。

**流程**：
- 用户上传 ChatGPT 导出的 `conversations.json`
- 转换器解析并生成标准会话格式
- 处理思考段、代码块、附件等边角
- 导入前预览，可选择性导入

---

#### G9 · 数据加密

**目标**：本地隐私保护。

**设计**：
- 设置密码，加密 localStorage 中的会话和 API Key
- 启动时输入密码解密
- 忘记密码只能清空（需明确警告）

**技术要点**：Web Crypto API + IndexedDB

---

#### G10 · 成本统计

**目标**：API 用户关心花多少钱。

**设计**：
- 按 provider / 按天 / 按模型统计 token
- 内置各平台价格表，估算费用
- 图表展示趋势
- 可导出 CSV

---

### 三、1.21 实施顺序建议

```
阶段 1：G1 记忆系统 + G2 命名空间隔离（RAG 深化）
   ↓
阶段 2：G3 多 Skill + G4 模板变量 + G5 引用跳转（体验优化）
   ↓
阶段 3：G6 工具调用（旗舰功能）
   ↓
阶段 4：G7 视觉输入 + G8 历史导入（扩展）
   ↓
阶段 5：G9 加密 + G10 成本统计（收尾）
```

## 🚫 不做清单（长期）

| 功能 | 原因 |
|---|---|
| 图像生成 | 与项目定位岔开，稀释主线 |
| 公网部署 / 多用户 | 涉及鉴权重写，得不偿失 |
| 插件市场 | 维护成本高，Skill 已足够灵活 |
| 主题皮肤商城 | 纯消耗精力，实际使用率低 |

## 📌 关键提醒

1. **1.20 是地基版本**，F3 拆分必须先行且不夹带新功能，否则回归测试失控。
2. **1.20 不要再加新功能**，现有 8 个已经接近上限。
3. **F2 多平台是最大变量**，接 API 会暴露很多边角问题，留足测试时间。
4. **版本号不是 KPI**，稳定交付比赶工重要。
